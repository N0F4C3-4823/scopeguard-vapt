# ScopeGuard evidence contract

Read this reference when changing testcase registration, execution, classification, evidence storage, POC rendering, or exports.

## Required result record

Each execution should be traceable without relying on prose generated by an LLM. At minimum, the persisted record needs:

- stable testcase ID and human label;
- target identity and authorized scope reference;
- controlled fixture ID and fixture expectation;
- deterministic classification: `FOUND`, `NOT_FOUND`, `NA`, or `INCONCLUSIVE`;
- the predicate/version that produced the classification;
- exact executed argv/command, working directory, and relevant tool version;
- byte-preserved stdout and stderr, exit code, timeout/termination reason, and execution timestamps;
- evidence artifact paths, byte hashes, and provenance linking each artifact to this execution;
- exporter/rendering version when a PNG, CSV, or ZIP is produced.

Do not fill unknown fields with guessed values. Missing required execution facts must keep the result `INCONCLUSIVE` or fail the export, according to the application's schema.

## Fixture matrix

The canonical registry is the only source of testcase count. A verification harness should derive its matrix from that registry and assert:

```text
registry IDs == 40 unique IDs
for every ID:
    fixture contract lists every supported state
    every declared state is executed through the real command/evidence path
    applicability behavior is explicit
    command failure/timeout/incomplete evidence remains INCONCLUSIVE
    evaluator result, persisted result, and exported row agree
coverage manifest links ID -> fixture -> execution -> result -> artifacts/hashes
```

Do not make a fixture pass by returning a precomputed classification. It must drive the same command/evidence/evaluator path used for the application. If a testcase legitimately has no meaningful `FOUND`, `NOT_FOUND`, or `NA` path, document that fixture contract and still prove its incomplete path is `INCONCLUSIVE`.

## POC layout and PNG rule

For each testcase condition, the status-specific POC path is:

```text
POCs/FOUND/<condition-specific-folder>/
POCs/NOT_FOUND/<condition-specific-folder>/
```

The condition folder must identify the condition without replacing the stable testcase ID in the surrounding result record. `NA` and `INCONCLUSIVE` are results, not negative POCs.

A PNG POC is valid only if its rendered payload is the exact executed command followed by the exact captured output, with no additional text or decoration. Validate the artifact against the captured bytes and the renderer contract. Put status, timestamps, hashes, target identity, exit code, and provenance in structured sidecars/result storage. Never “improve” a POC by adding a title, logo, border text, status badge, metadata caption, or synthetic output.

The renderer contract must specify how the recorded argv is serialized, whether stdout precedes stderr, the delimiter between command and streams, text encoding, and line-ending normalization. The PNG test compares the produced content with that contract and the original captured bytes. Do not render binary output as guessed text; preserve it as a sidecar or fail clearly.

## Export checks

CSV and ZIP exports must be tested from the browser and inspected as files. Check that:

- download completion and HTTP response succeed;
- the canonical CSV header/order, encoding, quoting, newline behavior, and exact status tokens are stable and match the product schema;
- duplicate or unknown testcase IDs are rejected, and untrusted text cannot become spreadsheet formulas under the application's documented CSV policy;
- every registered testcase is represented exactly as the product contract specifies;
- classifications preserve `INCONCLUSIVE` and `NA`;
- CSV values match persisted results and hashes;
- ZIP paths preserve the required POC structure and include the original evidence/provenance records plus a deterministic manifest;
- ZIP creation is scoped to the selected assessment/target, read-only, and rejects traversal, absolute paths, symlinks, and unsafe archive entries;
- missing or malformed required evidence fails closed, cleans up partial output, and never invents or reclassifies a result;
- no generated artifact contains invented command output or status text inside a PNG.
